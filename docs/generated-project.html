The generated project#

forja builds a project from recipes. Each recipe writes one concern: the API, the web app, the database, auth, an extra. The configuration decides which recipes run, and in which order. This page goes through them one by one. Run forja init <name> --yes --dry-run with your flags to see the exact tree.

Node recipes#

They run in this order: base, shared, core-hexagonal, db-postgres-docker or db-none, web, mobile, auth-sessions or auth-none, mailer-console, design-tailwind, e2e-web, extras-lint, ci, specgate. Each one runs only when the configuration asks for it.

The environment variables the recipes declare are collected in one root .env.example, grouped by recipe: APP_URL, DATABASE_URL, SESSION_TTL_DAYS and EXPO_PUBLIC_API_URL, depending on the choices.

How it is written#

Recipes write to an in-memory file system. When all of them have run, forja formats the TypeScript, JavaScript, JSON, CSS and Markdown files with Prettier, and only then writes to disk. A failure part way through leaves nothing behind, and --dry-run prints that same in-memory tree.

Contributing explains how a recipe is written.
