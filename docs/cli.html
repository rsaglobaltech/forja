CLI reference#

forja <command> --help prints the options of each command.

forja init#

Creates a new project in ./<name>. With no options it runs the wizard; with --yes or --config it asks nothing.

OptionValuesNotes
[name]lowercase letters, digits and hyphens, starting with a letterRequired with --yes. Also names the folder, the scope @<name> and the default Java package.
--backend <backend>node, spring, quarkusDefault node. Picks the set of defaults with --yes; with --config, replaces the file's. Any other value stops with Unknown backend.
--java-package <pkg>e.g. com.acme.shopJava only. Default com.<name> without hyphens.
--archunit / --no-archunitJava only. ArchUnit is on by default for Java. Ignored on Node.
--platforms <list>web, mobile, comma-separatedNode default web,mobile. Java: web, or "" for an API only.
--db <db>postgres-docker, noneDefault postgres-docker.
--auth <auth>sessions (Node), oauth2 (Java), noneNode default sessions, Java default oauth2.
--mailer <mailer>consoleUsed by Node sessions for password-reset emails.
--design <design>tailwind, noneDefault tailwind.
--tests <list>unit, integration, e2e-webDefault unit,integration. The list replaces the default.
--extras <list>lint, ci, docker, specgateNode default lint; Java default lint,docker,specgate. The list replaces the default.
--pm <pm>npm, pnpm, bunDefault npm. Java backends use npm only.
--yesAsk nothing: the defaults plus the flags.
--config <path>a forja.config.jsonStart from that file; the name and the flags override it. See Configuration.
--dry-runPrint the file tree and write nothing.
--skip-installDo not install the dependencies (and so do not adopt Specgate).
--skip-gitDo not run git init or make the first commit.

What init does, in order#

  1. Builds the configuration from the wizard, from --yes and the flags, or from --config and the flags.
  2. Validates it. An invalid configuration stops here, before anything is written.
  3. Renders every file in memory, then formats .ts, .tsx, .js, .jsx, .json, .css and .md files with Prettier.
  4. With --dry-run, prints the tree and stops.
  5. Refuses if ./<name> exists and is not empty.
  6. Writes the files.
  7. Unless skipped (and, in the wizard, after asking): git init -b main with a first commit chore: scaffold with forja, then the install with the chosen package manager, then the Specgate adoption when that extra is on.
  8. Prints the next steps.

Rejected combinations#

Each of these stops init with That configuration is not valid: followed by one line per problem:

CombinationMessage
Node with no platformplatforms: Choose at least one platform
Java with mobileplatforms: mobile with a Java backend is not supported yet: use --platforms web, or none for an API only
Java with --auth sessionsauth: with a Java backend, auth is oauth2 or none
Node with --auth oauth2auth: auth oauth2 needs a Java backend (spring or quarkus)
Node with --java-packagejavaPackage: --java-package needs a Java backend (spring or quarkus)
Node with the docker extraextras: docker is for Java backends; a Node project gets docker-compose with --db postgres-docker
e2e-web without webtests: e2e-web tests the web app: add web to the platforms
mobile without web, with authplatforms: mobile needs web too when there is auth: the auth API lives in apps/web (route handlers)
archunit: true on Node (from a config file)archunit: --archunit needs a Java backend (spring or quarkus)

forja add#

Adds a piece of the hexagon to the project you are in. Daily use shows where each file lands.

CommandArgumentWhat it adds
forja add usecase<module/Name>a use case, its test, and its wiring
forja add entity<[module/]Name>a domain entity and its test. Java needs the module.
forja add port<[module/]Name>an outbound port and an in-memory adapter. Java needs the module.
OptionCommandsEffect
--dry-runallprint what would change, write nothing
--req <id>usecasename this existing requirement (REQ-007) in the test
--title <title>usecasethe requirement's title, when Specgate creates it
--no-specusecasedo not create a requirement in Specgate
--no-adapterportthe port only, no in-memory adapter

--req that is not REQ-<digits>"..." is not a requirement id.

They exit with code 1. See forja and Specgate for --req, --title and --no-spec.

forja doctor#

No options. It checks the tools, the .env files and the architecture rules of the project you are in, and exits with code 1 when a check fails. Daily use lists every check.

forja --version#

forja --version (or -v) prints the installed version.
