A template is where a project starts. The rules are what keep it standing.

A starter template gets copied once. A month later the first shortcut lands: a page that queries the database, a use case that imports React. Nothing fails, so nothing stops it.

forja generates the rules with the code. On Java, ArchUnit fails the build when the domain reaches for Spring or one module uses another's infrastructure. On Node, forja doctor catches a UI import in the core. And forja add writes each new use case, entity and port where those rules expect it, already wired and already tested.

On the first run

What works before you write a line.

Sign-in, end to end

On Node: register, sign in, sessions in an httpOnly cookie, password reset. On Java: OAuth2 with Keycloak, the API as a resource server, and a realm with a demo user.

Tests from the first commit

vitest for the core's use cases; JUnit, Testcontainers and a real PostgreSQL for the API. Add --tests e2e-web and Playwright drives the sign-in in a browser.

Rules that are checked

ArchUnit on the API: a pure domain, no framework in the application, ports as interfaces, no cycles. forja doctor keeps the Node core free of UI imports.

Web and mobile, one core

Next.js and Expo import the same packages/core. One React version for both, the one Expo pins, so hooks never meet two copies.

Specgate, adopted

With the specgate extra, the project starts with a brief to fill in and a gate that runs your tests. Each use case you add names its requirement.

Plain code, no lock-in

What forja writes is yours: no runtime package, no generated folder to leave alone. Delete forja.config.json and the project still builds.

forja + Specgate

The use case and its requirement, in one step.

forja builds the structure. Specgate decides when a requirement is done: a scenario, a test that names it, and a suite that passes. forja add usecase creates the requirement, names it in the test, and regenerates the traceability matrix.

Questions people ask first.

Does forja stay in my project?

Only as forja.config.json, which forja add and forja doctor read. The generated code has no dependency on forja; delete the file and the project still builds and tests.

Can I run forja add on a project forja did not generate?

It needs the layout forja generates and a forja.config.json that describes it. On another layout it stops with an error before it writes anything.

Which combinations are supported?

Node with web, mobile or both; Spring Boot or Quarkus with a web app or as an API only. Mobile with a Java backend is not supported yet, and the CLI says so instead of generating half a project. See the command line reference.

Does it need GitHub Actions?

No. The ci extra writes a workflow if you want one; it is off by default. Everything forja generates runs locally with npm test.
